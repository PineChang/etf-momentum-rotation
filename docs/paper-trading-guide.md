## 1. 先建立整体认知

这套虚盘策略可以浓缩成一句话：

> 每个交易日收盘后，对 4 只 ETF 计算三个动量因子，横截面标准化并加权评分；结合趋势过滤、溢价安检、移动止损和止盈规则得到目标持仓；如果目标与当前持仓不同，就生成限价调仓计划，下一交易日开盘按真实开盘价模拟成交。

整体链路如下：

```text
tushare 中转站 / 东财行情
        │
        ▼
data/*.csv 本地日线缓存
        │
        ▼
三因子计算：乖离动量 + 斜率动量 + 效率动量
        │
        ▼
Z-Score 标准化 + 0.3 / 0.3 / 0.4 加权
        │
        ▼
绝对动量过滤 + 溢价入场门槛 + 禁买名单
        │
        ▼
最多选择 2 只目标 ETF
        │
        ▼
移动止损 / 固定止盈覆盖目标
        │
        ▼
state/trade_log.jsonl 写入交易计划
        │
        ▼
下一交易日读取真实开盘价，限价可成交则整批模拟成交
        │
        ▼
更新持仓、现金、峰值、交易日志和 HTML 仪表盘
```

最重要的设计点：

- **信号只在收盘数据完整后生成**，盘中不会把未定型的当天 K 线写进缓存；
- **成交发生在下一交易日开盘**，避免用今天收盘价决定今天又按今天价格成交的前视偏差；
- **回测与虚盘共用 `compute_target_set`**，所以目标持仓逻辑一致；
- **计划和执行都有幂等保护**，定时任务重复跑不会重复推进信号或重复成交；
- **溢价规则只拦新开仓，不因为溢价高而强制卖出已有持仓**。

## 2. 当前虚盘使用的策略版本

当前虚盘运行的是 **V3.1 推荐配置**，等价于：

```text
原文三因子动量轮动
+ 最多双持仓等权
+ 8% 移动止损
+ 25% 固定止盈
+ 绝对动量过滤
+ 7% 溢价入场门槛
```

对应 `cli.py` 中的预设：

```python
"v3.1": dict(
    n_hold=2,
    trailing_stop=0.08,
    min_momentum=0.0,
    take_profit=0.25,
    premium_max=0.07,
)
```

注意两个默认值：

- `cli plan` 默认使用 `--preset v3.1`，也就是当前虚盘配置；
- `cli backtest` 不传 `--preset` 时默认是 `original`，用于复现原文的全仓单标的版本，不是当前虚盘配置。

如果要回测当前虚盘策略，必须明确执行：

```bash
PYTHONPATH=src python -m etf_rotation.cli backtest --preset v3.1
```

## 4. 当前配置逐项解释

当前虚盘保存在 `state/params.json` 中的参数如下。该文件是虚盘运行状态，不提交到 Git；每次生成新计划时会自动更新。

### 4.1 三因子核心参数

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `momentum_day` | `25` | 乖离动量的回归窗口。对最近 25 个交易日的乖离率序列做线性回归。 |
| `bias_ma_n` | `20` | 乖离率的均线窗口，即 `close / MA20`。 |
| `slope_n` | `25` | 斜率动量窗口。对最近 25 个交易日收盘价做回归。 |
| `efficiency_n` | `25` | 效率动量窗口。对最近 25 个交易日的 OHLC 中枢价计算动量和流畅度。 |
| `w_bias` | `0.3` | 乖离动量标准化后的权重。 |
| `w_slope` | `0.3` | 斜率动量标准化后的权重。 |
| `w_efficiency` | `0.4` | 效率动量标准化后的权重。 |
| `rebalance_threshold` | `1.5` | 调仓阈值。挑战者必须显著强于当前持仓，才触发换仓。 |

权重相加为 1。效率动量权重最高，表示策略更重视“涨得流畅、路径干净”的标的。

### 4.2 资金与成本参数

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `initial_cash` | `100000.0` | 虚盘初始资金。当前虚盘从 10 万元开始。 |
| `commission` | `0.0001` | 单边佣金万分之一。买卖都收，没有印花税。 |

真实券商如果有最低 5 元佣金，小资金账户的实际成本会高于这里的假设。

### 4.3 当前启用的风控参数

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `n_hold` | `2` | 最多持有 2 只 ETF。建仓时按槽位等权，持有期间不再每日再平衡，权重会随涨跌漂移。 |
| `min_momentum` | `0.0` | 绝对动量过滤。最近 `slope_n=25` 个交易日原始收益率小于等于 0，则该标的不合格：候选不买，在持离场。 |
| `trailing_stop` | `0.08` | 移动止损。收盘价相对持仓期间最高收盘价回落超过 8%，目标中剔除该持仓。 |
| `take_profit` | `0.25` | 固定止盈。收盘价相对成本价上涨超过 25%，目标中剔除该持仓。 |
| `stop_cooldown_days` | `10` | 触发止损或止盈后的禁买期，10 个交易日内不买回同一标的。 |
| `premium_max` | `0.07` | 溢价入场门槛。最新已知场内溢价率超过 7% 时，不开新仓。只拦买入，不强制卖出已持有标的。 |

几个容易误解的点：

- `n_hold=2` 是**最多 2 只**，不是永远必须持有 2 只。趋势过滤或溢价过滤后，可能只持有 1 只，甚至空仓。
- `min_momentum=0.0` 使用的是原始价格收益，不是 Z-Score 后的相对分数。它解决的是“全池都没有绝对趋势”的问题。
- `trailing_stop` 的峰值是**持仓期间最高收盘价**，不是盘中最高价。
- `take_profit` 同样按收盘价判断，不是盘中触及就卖。
- `stop_loss` 当前虽然关闭，但 `stop_cooldown_days` 仍然有效，因为移动止损和固定止盈触发后也会进入禁买期。

### 4.4 当前关闭或未采用的参数

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `ma_filter_n` | `null` | 均线过滤。开启后，收盘价低于自身 MA(n) 则离场或不买。当前不用。 |
| `stop_loss` | `null` | 固定止损。开启后，对成本价浮亏超过阈值则离场。当前由移动止损承担主要亏损控制。 |
| `confirm_days` | `1` | 入场确认。空仓时要求标的连续 N 天评分第一才建仓。当前为 1，表示不额外增加确认等待。 |
| `drop_filter` | `false` | 急跌过滤实验规则。近 5 日出现单日大跌或连续大跌则不买。当前未启用。 |
| `dynamic_lookback` | `false` | 根据短长 ATR 波动率比例动态调整动量窗口。当前未启用。 |
| `premium_window` | `null` | 相对溢价均值过滤实验规则。回测表现不优于固定 7% 门槛，当前未采用。 |

动态窗口相关参数 `lb_min`、`lb_max`、`lb_ratio_cap`、`vol_short_n`、`vol_long_n` 只有在 `dynamic_lookback=true` 时才有作用；当前都只是保留的实验配置。

## 5. 数据从哪里来，什么时候刷新

### 5.1 行情主数据

ETF 日线缓存为：

```text
data/{symbol}.csv
```

例如：

```text
data/512890.csv
data/159949.csv
data/513100.csv
data/518880.csv
```

当前首选数据源是 **tushare 中转站**，东财 akshare 是兜底：

1. 优先请求 tushare 中转站的 `fund_daily`；
2. 前复权价格使用 `fund_adj` 的复权因子自行计算；
3. 保留 3 位小数，确保与交易所 ETF 最小价格单位一致；
4. 中转站失败时回退东财；
5. 两个来源都失败时直接报错，不写入可疑数据。

之所以强调 3 位小数，是因为 ETF 真实成交精度是 0.001。如果数据源把 1.208 圆整成 1.21，会直接污染成本、移动止损和净值。

### 5.2 缓存刷新规则

`data.py` 中的 `_needs_refresh` 决定什么时候更新：

| 缓存状态 | 当前时间 | 是否刷新 |
|---|---|---|
| 已有今天日线 | 任意时间 | 不刷新 |
| 缺昨天或更早的日线 | 任意时间 | 刷新，因为那些 K 线已经定型 |
| 只缺今天日线 | 16:00 前 | 不刷新，避免写入未收盘的半根 K 线 |
| 只缺今天日线 | 16:00 后 | 刷新 |

因此，白天看到行情缓存仍停留在上一交易日，是正常行为；晚间任务会补今天的完整日线。

### 5.3 增量更新与复权锚点

已有缓存时，不会每次全量重拉，而是拉取最近约 9 天的重叠区间：

- 如果重叠区收盘价与缓存一致，直接追加新数据；
- 如果不一致，说明前复权锚点可能因分红除息发生变化，需要全量重拉；
- 这样避免除息日后出现假跳空。

### 5.4 溢价数据

V3.1 的溢价安检依赖两类缓存：

```text
data/{symbol}.raw.csv   # 未复权场内收盘价
data/{symbol}.nav.csv   # 基金单位净值
```

溢价率定义为：

```text
premium = 未复权收盘价 / 单位净值 - 1
```

实现上使用严格 PIT（point-in-time）口径：T 日收盘生成信号时，当日单位净值通常尚未公布，所以只使用净值日期早于 T 的最后一条溢价。若 QDII 净值滞后（例如 513100 周一仍只有上周四净值），就使用最新已公布值，不会因为整体后移而再多丢一天。

溢价数据每次 `cli fetch` 时也会刷新。缺失或净值明显滞后时，命令行会打印警告，避免规则在旧数据上静默决策。

### 5.5 沪深 300 基准

仪表盘使用：

```text
data/000300.bench.csv
```

保存沪深 300 收盘价，用于展示：

- 策略净值 vs 沪深 300 净值；
- 策略回撤 vs 沪深 300 回撤；
- 同期沪深 300 收益；
- 策略超额收益。

## 6. 信号是怎么算出来的

每只 ETF 每个交易日都会计算三个原始因子。实现位于 `src/etf_rotation/factors.py`。

### 6.1 乖离动量：偏离趋势是否增强

先计算乖离率：

```text
bias = close / MA20
```

然后取最近 25 个交易日的 `bias`，把第一个值归一成 1，对序列做一元线性回归：

```text
乖离动量 = 回归斜率 × 10000
```

直观理解：

- 价格相对 MA20 的偏离越来越大，得分越高；
- 偏离开始收敛或转弱，得分下降；
- 它捕捉的是“强势是否还在加强”。

### 6.2 斜率动量：涨得多，还要涨得稳

取最近 25 个交易日收盘价，把第一天归一成 1，对价格序列做线性回归：

```text
斜率动量 = 10000 × 回归斜率 × R²
```

其中：

- `斜率` 表示涨得快不快；
- `R²` 表示趋势是否稳定、直线拟合好不好。

因此，不是只看涨幅，也惩罚上蹿下跳的上涨。

### 6.3 效率动量：上涨路径是否流畅

先计算每日中枢价：

```text
pivot = (open + high + low + close) / 4
```

对最近 25 个交易日的 `pivot` 取对数：

```text
momentum = 100 × (log(pivot_last) - log(pivot_first))
efficiency = |log(pivot_last) - log(pivot_first)| / Σ|diff(log(pivot))|
效率动量 = momentum × efficiency
```

直观理解：

- 分子是净位移；
- 分母是期间走过的总路程；
- 一路顺畅上涨，效率接近 1；
- 反复震荡后只涨一点，效率会很低。

### 6.4 横截面标准化

三个因子量纲不同，不能直接加权。因此对每个因子分别在 4 只 ETF 之间做 Z-Score：

```text
z = (factor - 因子均值) / 因子标准差
```

这里使用总体标准差 `ddof=0`。如果某天所有标的某因子完全相同，标准差为 0，则兜底为 1，避免除零。

### 6.5 综合评分

最终得分为：

```text
score = 0.3 × z(乖离动量)
      + 0.3 × z(斜率动量)
      + 0.4 × z(效率动量)
```

得分高只表示在当前 4 只 ETF 中相对更强，不表示它一定有正收益；所以还需要 `min_momentum` 做绝对趋势过滤。

## 7. 目标持仓是怎么选出来的

目标选择位于 `scoring.py` 和 `backtest.py`。

### 7.1 先过滤候选池

在正式选 top-2 之前，会依次处理：

1. 去掉仍在禁买期的标的；
2. 去掉绝对动量不合格的标的；
3. 对未持有标的检查入场门槛，例如溢价是否超过 7%。

绝对动量过滤的判断是：

```text
close_today / close_25_trading_days_ago - 1 <= 0
```

满足这个条件就不合格。

### 7.2 再按排名填充最多 2 个槽位

`select_targets` 的规则是：

1. 当前空仓或存在空槽位时，排名靠前的合格标的直接补位；
2. 槽位已满时，新的挑战者必须显著强于当前最弱持仓，才替换。

阈值比较不是简单要求“挑战者排第一”，而是：

```text
挑战者得分 > 在持最弱者得分 + 0.5 × |在持最弱者得分|
```

当在持者得分为正时，它等价于文章中的：

```text
挑战者得分 > 在持者得分 × 1.5
```

当在持者得分为负时，这种写法避免“乘以 1.5 后反而更容易换仓”的反向问题。

### 7.3 为什么评分第一不一定买入

常见原因有四个：

1. 它的绝对动量不合格；
2. 它的溢价超过 7%，被入场门槛拦截；
3. 当前持仓没有弱到触发 1.5 倍换仓阈值；
4. 它触发入场确认不足、禁买期或其他风控条件。

所以仪表盘上的“最新评分”要结合溢价、风控和当前持仓一起看。

## 8. 风控规则的执行顺序

每天生成目标持仓时，大致顺序如下：

```text
1. 计算三因子和综合评分
2. 剔除禁买期标的
3. 应用绝对动量过滤
4. 对未持有标的应用溢价入场门槛
5. 选择最多 2 只目标 ETF
6. 推进评分连击
7. 空仓时检查入场确认天数 `confirm_days`
8. 更新持仓期间最高收盘价 peak
9. 检查移动止损和固定止盈
10. 触发止损/止盈的标的从目标中剔除，并进入禁买期
```

最后一步的优先级最高。即使某只 ETF 评分仍然很高，只要当天收盘触发移动止损或止盈，也不会留在目标持仓中。

当前移动止损触发条件：

```text
close < peak × (1 - 0.08)
```

当前固定止盈触发条件：

```text
close > cost × (1 + 0.25)
```

触发后，该标的 10 个交易日内不能重新买入。

## 9. 每天完整交易流程

### 9.1 前一晚：收盘后生成计划

晚间任务执行：

```bash
python -m etf_rotation.cli fetch
python -m etf_rotation.cli plan
python -m etf_rotation.cli dashboard
python -m etf_rotation.cli notify --task evening
```

对应脚本：

```bash
./scripts/daily_paper.sh evening
```

做的事情依次是：

1. 更新 4 只 ETF 的完整日线；
2. 刷新溢价 raw/nav 缓存；
3. 刷新沪深 300 基准；
4. 用最新完整收盘数据计算目标持仓；
5. 如果目标变化，生成卖出和买入限价单；
6. 更新风控状态，例如峰值、禁买名单、评分连击；
7. 把计划追加到 `state/trade_log.jsonl`；
8. 重新生成 `state/dashboard.html`；
9. 发送 Bark 任务摘要，并记录 `state/notify_status.json`。

如果同一信号日、同一参数已经生成过计划，晚间补跑会打印：

```text
信号日 YYYY-MM-DD 的计划已生成过且参数未变,跳过
```

这是幂等保护，不是失败。

### 9.2 次日早上：补取数据并执行计划

早间任务执行：

```bash
python -m etf_rotation.cli fetch
python -m etf_rotation.cli plan
python -m etf_rotation.cli execute
python -m etf_rotation.cli dashboard
python -m etf_rotation.cli notify --task morning
```

对应脚本：

```bash
./scripts/daily_paper.sh morning
```

为什么早上还要 `fetch + plan`：

- 如果前一晚电脑睡眠，晚间任务没跑，早上可以补；
- 如果数据已经新鲜，命令会自动跳过，不会重复写计划；
- 这样可以容忍 macOS 睡眠导致的漏跑。

### 9.3 `execute` 的实际逻辑

`execute` 读取 `trade_log.jsonl` 中最近一份计划，然后：

1. 检查计划是否有订单；
2. 检查这份计划是否已经成交过；
3. 检查计划生成日期是否超过 4 天；
4. 通过 `data_source.calendar()` 确认今天是否交易所开市；确认休市则直接跳过，不再反复拉开盘价；
5. 只拉取订单涉及 ETF 的当日开盘价；
6. 判断开盘价是否满足限价；
7. 全部可成交则整批成交，否则整批放弃；
8. 更新现金、持仓、已实现盈亏和成交日志。

计划太旧时不会执行：

```text
计划生成于 YYYY-MM-DD,已过 N 天,信号可能过时——请先 cli plan 重新生成
```

### 9.4 非交易日怎么办

周末和节假日没有真实开盘价。项目会优先读取 `ETF/data_source` 的交易日历；确认休市时，`execute` 直接跳过，不会反复等待开盘价。日历不可用时才回退到原逻辑，由开盘价接口判断非交易日。

晚间 cron 当前是“每天”运行，所以周末也会做数据刷新、计划幂等检查、仪表盘更新和 Bark 摘要推送；这属于正常维护，不代表周末会交易。

## 10. 订单、成交与记账规则

### 10.1 限价单怎么定价

计划使用信号日收盘价作为参考价：

```text
买入限价 = 信号日收盘价 × 1.01
卖出限价 = 信号日收盘价 × 0.99
```

并四舍五入到 3 位小数。

含义：

- 买入最多接受比参考价高 1% 的开盘价；
- 卖出最低接受比参考价低 1% 的开盘价；
- 跳空超过 1% 时，开盘价不成交。

### 10.2 开盘价是否满足成交

`execute` 使用真实开盘价判断：

```text
买入：今日开盘价 <= 买入限价，才成交
卖出：今日开盘价 >= 卖出限价，才成交
```

实际记账价格是**开盘价**，不是限价。

### 10.3 为什么整批执行或整批放弃

如果一组计划里既有卖出又有买入，部分成交会造成：

- 卖出的现金尚未释放；
- 买入预算不足；
- 槽位权重被破坏。

所以当前实现采用原子语义：

> 任意一笔限价单在开盘价未成交，本批全部不执行；稍后可以安全重跑。

这不是说真实限价单盘中一定不会成交，而是虚盘只按“开盘时刻”做一次确定性模拟。

### 10.4 买入金额怎么分配

当前 `n_hold=2`，所以总资产理论上分成 2 个槽位：

```text
slot = 账户总估值 / 2
```

买入时：

```text
budget = min(slot, 当前现金)
```

建仓时等权；之后不会每天调回 50/50，而是让权重随涨跌自然漂移。

### 10.5 份额和佣金怎么计算

买入份额：

```text
shares = budget × (1 - commission) / fill_price
```

现金减少：

```text
cash -= budget
```

也就是说，佣金通过“实际买到的份额略少”体现。

卖出回款：

```text
proceeds = shares × fill_price
commission = proceeds × 0.0001
cash += proceeds - commission
```

已实现盈亏：

```text
realized_pnl += proceeds - commission - shares × cost
```

### 10.6 幂等保护

同一计划是否已成交，用以下两个字段匹配：

```text
plan_date + data_asof
```

如果已经有对应 `fill` 记录，再次执行 `execute` 会拒绝：

```text
计划 YYYY-MM-DD 已执行过,拒绝重复执行
```

`execute_plan` 本身不是幂等函数；防重复依赖外层 `StateStore.plan_executed`。

## 11. 最近一个真实虚盘示例

以下示例来自 2026-10-19 白天的本地状态；行情截至 2026-10-16 收盘。它是写本文时的快照，之后应以仪表盘为准。

### 11.1 首笔建仓

2026-10-07 的计划目标包含 `512890`，计划买入限价：

```text
1.208
```

2026-10-07 实际开盘价：

```text
1.197
```

因为：

```text
1.197 <= 1.208
```

所以买入成交。

当时总资金 100,000 元，`n_hold=2`，一个槽位预算 50,000 元。买入份额约为：

```text
50,000 × (1 - 0.0001) / 1.197 = 41,766.917 份
```

成交后：

```text
现金 = 50,000 元
持仓 = 512890，约 41,766.917 份
成本 = 1.197
```

### 11.2 2026-10-16 收盘后的计划

最近一份有效计划的主要评分为：

| ETF | 综合评分 | 溢价口径说明 | 处理 |
|---|---:|---|---|
| `512890` | `+0.4760` | `-0.25%` | 继续持有 |
| `513100` | `+1.1641` | 历史日志旧口径 `+19.55%`；修复后按当时最新净值重算为 `+15.72%`；10-16 净值后续公布后为 `+20.52%` | 三个值都超过 7%，禁止新开仓 |
| `159949` | `-1.5226` | `+0.23%` | 不进入目标 |
| `518880` | `-0.1175` | `-0.20%` | 不进入目标 |

这份计划很能说明 V3.1 的关键逻辑：

- 如果只看评分，`513100` 高于当前持有的 `512890`；
- 但 `513100` 的溢价无论按历史日志、修复后当时口径，还是后续补发净值口径，都高于 `premium_max=7%`；
- 因此它不能作为新开仓候选；
- 最终目标仍是 `512890`，订单为空。

> 2026-10-19 修复了 QDII 净值滞后时溢价多错一天的问题。历史 `trade_log.jsonl` 中的 19.55% 是修复前记录；15.72% 是修复后按当时已公布净值的重算值；20.52% 是 10-16 净值后来补发后的值。三者不影响当日结论。

所以当天 `execute` 的结果是：

```text
无订单，无需执行
```

### 11.3 当前持仓风控线

快照中的 `512890`：

```text
成本 = 1.197
最新收盘 = 1.219
持仓期间最高收盘 peak = 1.231
```

移动止损线：

```text
1.231 × (1 - 0.08) = 1.13252
```

固定止盈线：

```text
1.197 × (1 + 0.25) = 1.49625
```

因此：

- 收盘价跌破约 `1.133`，下一信号会把 `512890` 从目标中剔除；
- 收盘价涨破约 `1.496`，触发止盈并进入 10 个交易日禁买期；
- 在此之前，继续持有还是换仓由评分、阈值、绝对动量和溢价规则共同决定。

## 12. 本地状态文件分别是什么

虚盘状态保存在 `state/`，该目录已在 `.gitignore` 中排除，不会提交到 GitHub。

| 文件 | 内容 | 什么时候更新 |

## 13. 自动化调度

当前 cron 设计为 4 个时隙：

```cron
31 9  * * 1-5  /Users/apple/Desktop/AIExp/ETF/etf-momentum-rotation/scripts/daily_paper.sh morning
31 10 * * 1-5  /Users/apple/Desktop/AIExp/ETF/etf-momentum-rotation/scripts/daily_paper.sh morning
30 20 * * *    /Users/apple/Desktop/AIExp/ETF/etf-momentum-rotation/scripts/daily_paper.sh evening
30 21 * * *    /Users/apple/Desktop/AIExp/ETF/etf-momentum-rotation/scripts/daily_paper.sh evening
```

含义：

| 时间 | 任务 | 目的 |
|---|---|---|
| 工作日 09:31 | `morning` | 开盘后补取数据、生成/确认计划、执行计划、刷新仪表盘 |
| 工作日 10:31 | `morning` | 第一次早间任务失败或电脑睡眠后的补跑 |
| 每天 20:30 | `evening` | 获取当天完整日线，生成次日计划，刷新仪表盘 |
| 每天 21:30 | `evening` | 晚间任务失败后的补跑 |

macOS 注意事项：

- cron 可以访问 `~/Desktop`，launchd 子进程可能受 TCC 权限限制，所以项目选择 cron；
- cron 不会主动唤醒睡眠中的 Mac；
- 如果电脑到点休眠，需要靠下一个时隙补跑；
- 可以配置工作日定时唤醒：

```bash
sudo pmset repeat wakeorpoweron MTWRF 09:25:00
```

## 16. 常见问题与排查

### 16.1 为什么白天数据还停在上一交易日

因为当天尚未收盘，项目故意不把盘中未定型 K 线写入日线缓存。16:00 后或晚间任务会补当天完整日线。

### 16.2 为什么周日也有任务日志

晚间 cron 是每天运行，周日也会做缓存维护和仪表盘更新。但周日没有开盘价，不会发生真实或虚盘成交。

### 16.3 为什么评分第一没有买

优先检查：

1. 溢价是否超过 7%；
2. 绝对动量是否小于等于 0；
3. 是否仍在 10 日禁买期；
4. 当前持仓是否未达到 1.5 倍换仓阈值；
5. 计划是否已经生成但尚未到执行日。

### 16.4 为什么计划显示无订单

通常表示：

- 当前持仓就是目标持仓；
- 或者目标为空仓且账户已空仓；
- 或者新候选被溢价、趋势或禁买规则拦截。

这不一定是异常。

### 16.5 为什么早上计划失败但下午重跑成功

数据源可能出现临时 DNS、超时或连接重置。只要后续完整流程无 Traceback、无回退警告，并刷新成功，就可以视为恢复。

重点看最近一次任务块中是否有：

- `Traceback`；
- `tushare 中转站取数失败`；
- `回退东财`；
- `溢价数据刷新失败`；
- `基准刷新失败`。

### 16.6 什么是 `data_lag` 警告

策略要求 4 只 ETF 在相同交易日可比。只要某一只缺当天 bar，交集对齐会把全池信号日回退到更早的共同交易日。

出现 `data_lag` 说明：

- 某只 ETF 停牌或数据源缺口；
- 当前信号没有使用该标的最新行情；
- 应检查对应缓存和数据源。

### 16.7 为什么溢价数据会有“滞后”提示

单位净值通常晚间才公布，QDII 还可能更晚。项目会比较未复权收盘价日期和净值日期，如果净值落后太多，就认为溢价数据陈旧，提醒不要把它当成可靠的当日值。`513100` 属于美股 QDII，T+2 内披露都算正常节奏；只有超过其正常披露窗口时才升级为陈旧警告。

### 16.8 为什么开盘没有成交

常见原因：

- 买入开盘价高于 `收盘价 × 1.01`；
- 卖出开盘价低于 `收盘价 × 0.99`；
- 今日不是交易日；
- 实时开盘价尚未生成；
- 同批另一笔订单未成交，导致整批放弃。

可以稍后重新运行 `execute`，但只有“开盘价尚未生成/数据源临时失败”这类情况会改变结果。如果当日开盘价已经确定且不满足限价，当天重跑仍会失败，需要等新计划或下一交易日。

### 16.9 为什么 10:31 没有看到补跑日志

先检查：

```bash
crontab -l
grep '^===' logs/paper.log
```

可能原因包括：

- 电脑当时睡眠；
- cron 没有触发；
- 脚本未能启动；
- 日志被其他手动运行覆盖时间点。

没有任务头就表示没有完整执行 `daily_paper.sh`。

### 16.10 不建议手工改哪些文件

不建议直接修改：

- `state/state.json`；
- `state/trade_log.jsonl`；
- `state/equity.csv`。

这些文件之间有隐含一致性。例如交易日志显示某计划已成交，而 `state.json` 没对应持仓，就会破坏后续计划。排查时先只读，不要边猜边改。

## 17. 这套虚盘和真实交易的差异

### 17.1 成交价假设

虚盘按“开盘价满足限价则成交”模拟；真实交易中，限价单可能：

- 开盘部分成交；
- 开盘后一段时间才成交；
- 全天不成交；
- 因流动性或价格笼子规则失败。

### 17.2 成本假设

当前只考虑万分之一佣金，没有考虑：

- 最低 5 元佣金；
- 买卖价差；
- 市场冲击；
- 申赎、跨境 ETF 的额外限制；
- 真实账户资金出入金。

### 17.3 份额假设

虚盘允许小数份额；真实 A 股 ETF 通常有最小申报数量要求，实际买入份额会取整。

### 17.4 分红与复权

信号使用前复权序列便于连续比较；真实账户资产会受现金分红、份额变化和除息影响。长期虚盘与真实账户可能出现口径差异。

### 17.5 净值与溢价
