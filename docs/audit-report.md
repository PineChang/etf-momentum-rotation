## 一、审计方法

不读结论先跑实验。所有检验用独立脚本从 `data/*.csv` 缓存直接重算(绕过网络与项目自带脚本),共 6 组:

**A. 未来函数截断实验(最硬的证据)**——在 8 个随机日期截断数据分别回测:若存在任何前视偏差,截断版的持仓/成交必然与全量版不同。结果 8/8 截断日前的净值前缀与交易清单**逐笔完全一致**(含 96~320 笔交易)。

```
截断 2020-04-29 / 2021-09-01 / 2021-11-09 / 2022-01-28 / 2022-06-15 / 2022-08-31 / 2022-11-25 / 2023-02-01
净值前缀一致=True ×8   交易逐笔一致=True ×8   ==> PASS 无未来函数
```

代码级复核与截断实验相互印证:

- 因子计算入参 `data[s].iloc[: t + 1]`(`backtest.py:120`)——只含 T 日及之前;
- 信号日收盘评分 → `pending` → **次日开盘成交**(`backtest.py:93-113`),不存在"用收盘价评分又用同一收盘价成交";
- 止损/止盈用 T 日收盘价判断、T+1 开盘离场(`backtest.py:143-152`),不偷看 T+1 行情;
- 项目自带测试 `test_no_lookahead` 只检查首笔成交日晚于 warmup,证据较弱;本次截断实验是强得多的检验,依然通过。

**B. 复权一致性(数据完整性)**——qfq(前复权)会因除息改写历史价格,若 qfq 缓存存在锚点错位,日收益会在除息日出现假跳空。用 hfq(后复权,无未来信息)交叉对照:

```
512890 / 159949 / 513100 / 518880:日收益最大偏差 ≤ 0.17%,>0.5% 偏差仅 1 天(2026-09-28,
为当日盘中两次抓盘的时点差,自愈性问题),无任何除息断点 ==> qfq 缓存当前内部一致
```

数据质量:4 只标的无重复日期、无 NaN、无非正价格、无异常跳空(最长间隔 11 天=春节)。

**C. rand10 复算**——用相同种子(42)重新生成 10 个窗口,从缓存数据重跑全周期回测后切片:

```
10 窗口收益复算 vs summary.csv 最大偏差 3.05e-16(浮点噪声级别)==> 报告数字真实、可复现
```

**D. V3 vs 等权基准("全正"的含金量)**——每窗口对比"期初等权买入 4 只 ETF 持有到期末":

```
win01~win10:V3 全部跑赢等权基准(10/10)
例:win06(2021-12→2022-11)V3 +6.3% vs 基准 -7.8%;win10(2025-07→2026-07)V3 +59.9% vs 基准 +31.0%
==> 全正不是靠 2020/2025 普涨行情的 beta,轮动本身有超额
```

## 二、过拟合专项审计

### 2.1 调参过程存在数据窥探(事实认定)

`output/drawdown_experiments_r1~r6.csv` 显示经历了 **6 轮、累计上百个配置**的全样本实验(评估区间都截至 2026-09-28),V3 的止盈 `take_profit=0.25` 是最后一轮在全样本上挑的,**当时未做样本外验证**。这是教科书式的多重检验/数据窥探流程,认定成立。

### 2.2 但四项独立证据表明 V3 未被窥探污染

**(1) Walk-forward:IS 选参恰好选中 V3**(本次复验,非引用文档):

| 候选(假设 2022 年底只能看到 2019-2022) | IS 卡玛 | OOS(2023-2026)卡玛 | OOS 年化 | OOS 回撤 |
|---|---|---|---|---|
| 原文 | 1.46 | 1.40 | +45.1% | -32.2% |
| top2 裸 | 1.47 | 1.69 | +28.3% | -16.7% |
| trail6 | 1.47 | 1.80 | +23.8% | -13.2% |
| trail8(推荐) | 1.58 | 1.95 | +25.8% | -13.3% |
| trail10 | 1.18 | 1.96 | +26.0% | -13.3% |
| **trail8+tp25(V3)** | **1.93(最优)** | **2.29** | **+30.4%** | **-13.3%** |

**只用样本内数据选卡玛,第一名就是 V3**;且 V3 样本外卡玛(2.29)> 样本内(1.93)。过拟合策略的典型症状是样本外塌陷,这里恰恰相反。

**(2) 止盈参数是平台不是尖点**(含样本内/外双验证):

| take_profit | 全样本卡玛 | IS 卡玛 | OOS 卡玛 | OOS 年化 |
|---|---|---|---|---|
| 无(V2) | 1.72 | 1.58 | 1.95 | +25.8% |
| 15% | 1.50 | 1.72 | 1.42 | +19.0% |
| 20% | 1.93 | 1.84 | 2.18 | +28.3% |
| **25%(V3)** | **2.01** | **1.93** | **2.29** | **+30.4%** |
| 30% | 1.97 | 1.81 | 2.22 | +29.4% |
| 40% | 1.86 | 1.81 | 2.01 | +26.6% |

20%~30% 全区间在 IS 与 OOS 都优于不止盈,25% 同时是 IS 与 OOS 的局部最优——若 25% 是噪声尖点,IS/OOS 不可能同向。

**(3) README "三个分时段止盈全优于不止盈" 复验:成立**(2019-21 卡玛 2.49 vs 2.01;2022-24 1.30 vs 1.11;2025-26 4.67 vs 3.12)。

**(4) 股票池替换**(引用项目验证,逻辑我已复核):换同类池/全新池后,风控机制的降回撤效果保持,但**收益水平强烈依赖原池含纳指/创业板这类高动量资产**——策略机制可迁移,收益不可迁移。

### 2.3 对"10 个随机一年全正"的正确解读

- **它不是 10 个独立样本**:13/45 个窗口对日历重叠(win02/03/04 几乎同一段 2020-2021 行情),且全部窗口都在调参用过的数据内——**这是"样本内一致性"检验,不是样本外检验**。
- 真正的样本外证据是 2.2 的 walk-forward(2023-2026 段),那一段 V3 年化 +30.4%、回撤 -13.3%。
- 弱市窗口(win06/07,2022 年)只有 +6~7%、夏普 0.5——全正但并不神奇,熊市里策略靠空仓过滤保正,这是 min_momentum=0 的设计效果,合理。

## 三、发现的问题(按严重度排序)

### R0(实盘模块与回测脱节,高危——若用于实盘)live.py 根本不是 V3

第二轮代码级复查(运行时探针验证)发现:`live.py`(cli `plan` 命令调用的实盘计划模块)**只实现了原文策略**——`make_plan` 用单持仓版 `select_target`,源码中不包含 `n_hold`/`select_targets`/`trailing_stop`/`min_momentum`/`take_profit`/`stop`/`cooldown`/`confirm_days` 中的任何一项(探针全文检索确认)。

**后果:如果拿 `cli plan` 生成实盘计划,实际执行的是"原文全仓单标的+无限价风控"策略,而不是回测里验证过 26.6%/-13.3% 的 V3。** 这是"回测一套代码、实盘另一套代码"的经典量化事故源。回测结论不受影响(V3 数字全部出自 backtest.py),但**在 live.py 补齐 V3 逻辑之前,不能拿它做实盘**。

附带两个 live.py 内部缺陷(同为探针实测):
- `execute_plan` 空仓首日建仓:`budget = cash if cash>0 else position.cost + position.realized_pnl`,初始 `Position()` 两者皆 0,`initial_cash` 全程未被使用 → **实测买入 0.0000 份**;
- 限价单锚定**昨日收盘价**(买=昨收×1.01,卖=昨收×0.99),开盘跳空超 1% 时不会成交——与回测"开盘价必成交"假设不一致。

### R1(逻辑缺陷,中高)调仓阈值 "×1.5" 在负分区退化

`scoring.py:75` / `scoring.py:48`:判换仓用 `challenger > weakest * 1.5`。当在持者得分为负时,`×1.5` 让不等式**更容易**通过而不是更难——阈值"防换血"机制反向失效。实测(V3 全周期):

```
阈值比较 1901 次中,最弱在持者得分为负的 365 次(19%);
其中 54 次发生真实逻辑反转——换到了评分更低的标的;
负分区比较的换仓率 47%(正分区的阈值约束形同虚设)
```

- **为什么没推翻回测**:回测与未来实盘跑的是同一段代码,行为自洽,绩效数字已包含此缺陷的影响;且它无前视。
- **但需知晓**:这与设计意图("挑战者须显著强于")和原文语义不符,是 kimi-k3 开发时从文章伪代码照搬的隐患。**若修复(改用差值阈值或排名比较),V3 的参数需要全部重新验证,不能直接沿用现在的推荐值。**

### R2(方法论,中)调参流程的数据窥探

见 2.1/2.3。6 轮上百配置的全样本搜索 + 随机窗口全落在样本内。尽管四项证据显示这次"侥幸"未被污染,但**这个流程本身不可复制**——下次同样流程未必这么幸运。今后任何参数改动都应先冻结 IS 区间选参、再看 OOS。

### R3(建模偏乐观,中低)成本与成交假设

- 佣金万 1、无最低消费、无滑点、开盘价全额成交、无容量约束。实测敏感性:

```
单边成本 0.01% → 年化 +26.6%(现假设)
单边成本 0.05% → +24.4% / 回撤 -14.1%(更接近真实:佣金+点差+冲击)
单边成本 0.10% → +21.8% / -15.1%
单边成本 0.20% → +16.6% / -17.7%
```

年均约 46 次往返、小资金下万 5 单边是合理估计 → **实盘预期年化应从 26.6% 下调至 ~24% 量级**,结论方向不变。

### R4(潜伏 bug,中)qfq 缓存增量更新会在除息后引入价格断点

`data.py:50-59` 增量更新时只**追加**新行。前复权的锚点是"最新价",每次分红后整条历史 qfq 序列会被数据源整体改写,而缓存里的旧行**不会被改写**→ 未来某次分红后增量更新,将在除息日产生假跳空,污染收益与信号。当前缓存经 B 检验无此问题(应是整段下载的),**但这是个定时炸弹**。建议:增量更新时改为整段重拉,或改用 hfq(锚定上市日,不受影响)。

### R5(口径,低)夏普用 cagr 而非均值收益

`metrics.py:18` `(cagr - rf) / ann_vol`,cagr ≤ 算术均值收益(波动拖累),分子偏大。V3 全样本:cagr 口径夏普 1.73,均值口径 1.61。是美化不是 bug,对外报数建议用均值口径。

### R7(口径瑕疵,低,第二轮新增)指标与报告的小口径问题

- **cagr 年化分母**:用 `252/len(equity)`,而 n 个净值点只有 n-1 个交易日收益,应为 `252/(n-1)`。实测方向是**轻微低估**年化(244 点样例 -0.15 个百分点,相对 -0.5%)——保守方向的误差,不美化结果,但口径不严谨。
- **胜率/往返盈亏未扣佣金**:`metrics.py:48` pnl = 价差×份额,654 笔成交的总佣金 8,399 元未计入。量级对胜率影响可忽略,但严格口径应含佣金。
- **report_trades.csv 标签误导**:`report_last_year.py:135` 导出的是**全周期**交易流水,未按一年窗口过滤(报告标题是"一年期报告")。往返配对表是过滤过的,不受影响。
- **"等权"只在建仓时成立**:`backtest.py` 槽位等权只在买入时点计算,持仓期间不 rebalance,权重随涨跌漂移。文档描述"双标的等权"略有夸大,非 bug。

### R8(脆弱写法,低,第二轮新增)`top` 变量的作用域隐患

`backtest.py:139` 引用的 `top` 只在 `not candidates.empty` 分支(`backtest.py:134`)里赋值。candidates 为空时 `target_set` 必为空集、`and target_set` 短路兜底——**当前逻辑正确**,但正确性依赖两个相距 5 行的隐式不变量,重构时极易踩出 NameError。建议把 `top` 的计算挪进同一分支。

### R6(固有偏差,无法修复,中)股票池幸存者偏差

4 只 ETF 是原文作者事后选的(含纳指、黄金这两个 2019-2026 大牛资产)。换池检验已证明收益水平依赖池子质量。这不是代码能修的,是策略收益来源的固有前提,**实盘预期必须打折**(项目验证文档自己也是这么承认的,这点诚实)。

## 五、给实盘的建议

1. **`live.py` 补齐 V3 逻辑之前,不要用 `cli plan` 做实盘/模拟盘**——它跑的是原文策略(全仓单标的、无止损止盈),不是验证过的 V3。补齐时注意 V3 需要:双持仓、移动止损、动量过滤、止盈、禁买期;
2. 把预期从"回测 26.6%"调整为"扣成本 ~24%、考虑选池偏差后再打折";
2. **修复 R4 之前不要长期依赖 qfq 缓存增量更新**(或改为每次全量重拉);
3. R1 的阈值缺陷建议列入待办:修复后必须在 IS 区间重新选参并复验 OOS,**不要**带着旧参数直接换新逻辑;
4. 每季度用新增行情做一次滚动 walk-forward(数据截至今天,最新一段 OOS 2023-2026 仍然有效,建议持续监控是否衰减);
5. 单数据源(东财/腾讯免费行情)与官方复权可能有细微差异,模拟盘对账时留意。

### 7.3 多重检验量化(Deflated Sharpe——本审计对 V3 最不利的发现)

重现项目调参时实际探索的参数空间(权重×阈值网格 264 + 风控变体 144 = **408 组**),全部在样本内(2019-2022)计算 IS 夏普:

```
408 次试验 IS 夏普:均值 1.29,标准差 0.19,最大 1.70
V3 的 IS 夏普:1.51(排名 38/408)
试 408 次纯数据挖掘的期望最大虚假夏普:≈1.95
```

**结论:V3 的 IS 夏普(1.51)低于纯数据挖掘的期望上限(1.95)——单看样本内数字,无法排除过拟合。** 这是 Deflated Sharpe 框架(Bailey & López de Prado)的直接应用:试了 408 组参数后,"最好的那组"夏普达到 1.9 左右纯属运气也是正常的。

**但 V3 的可信度不押在 IS 上**:其样本外(2023-2026,选参时不可见)夏普 **1.77 > IS 1.51**,与数据挖掘策略"样本外塌陷"的典型形态相反;且 walk-forward 已证明只用 IS 选参恰好选中 V3。OOS 段是当前能拿到的最强证据,也是唯一需要持续监控的指标。

### 7.4 深检后的最终结论

1. **无未来函数**:截断实验+扰动实验+逐笔取证三重锁定,代码层排除;
2. **回撤控制是真的**:结构性的(双持仓+移动止损+动量过滤),所有随机窗口回撤 ≤12.9%,不依赖行情;
3. **收益必须打折预期**:合理锚定区间 **12~18% 年化**(OOS alpha 部分),而非 28%;再扣点差/滑点(黄金ETF 点差约 0.1%,回测只计万 1 佣金)再减 2-3 个点;
4. **策略可信度押在 OOS 上**:IS 无法自我证明,建议实盘前先跑模拟盘,持续用新数据监控 OOS 夏普是否衰减——这是比任何回测都重要的活体检验。

**一句话:代码没有骗人,但行情帮了忙。策略是真的,28% 是时代的。**
