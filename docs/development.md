## 3. 关键实现决策与权衡

1. **文章未披露 3 个窗口参数**(BIAS_N / SLOPE_N / 效率窗口)
   → 显式假设 20/25/25,写入 `config.py` 注释与 README,且全部支持 CLI 覆盖;
   回测结果(当时口径年化 42.49% / 净值 13.72x;第四轮口径 42.51%)与文章披露(42~43%、13x)高度吻合,反证假设合理。

2. **阈值比较的边界**:文章语义为"超过 1.5 倍",实现为严格大于 `>`,
   恰等于 1.5 倍时不调仓(有测试锁定该行为)。

3. **负得分下的阈值语义**(第一轮当时):Z-Score 后得分可负,`challenger > 1.5 × holder`
   在 holder 为负时恒真 → 当时**忠实保留了文章字面逻辑**(弱持仓尽快换掉),未做"改良"。
   > ⚠️ **该决定已在第二轮被推翻**:第三轮审计发现这不是"风格选择"而是**逻辑缺陷** ——
   > `×1.5` 在负分区让不等式更容易成立,阈值"防换血"机制反向失效,实测 1901 次比较中
   > 54 次换到了**评分更低**的标的。现已改为对称语义(挑战者需超出 `|在持者|×(阈值-1)`),
   > 正分区与文章公式完全等价。见 `docs/audit-report.md` §六 R1 与 §9.2。

4. **TDD**:先写因子/评分测试(手算期望值 + np.polyfit 独立验证),再写实现;
   回测引擎用合成数据(单边上涨 vs 横盘)锁定轮动、无前视、复利、佣金四大行为。

## 6. 降回撤专项(2026-09-28 追加)

用户反馈 -32.2% 回撤过大 → 系统性实验:

1. **引擎改造**:`StrategyConfig` 增加 4 个默认关闭的风控开关;backtest 支持空仓状态
   (原来 `pending=None` 与"无信号"歧义,引入 `_UNSET` 哨兵区分)。
2. **关键踩坑**:
   - 绝对动量过滤用 Z-Score 无效——横截面标准化后全池下跌时仍有"相对最高分",
     改用原始 N 日收益(`min_momentum`);
   - 止损后被立即买回同一标的(损-追高循环)→ 增加 `stop_cooldown_days` 禁买期;
   - 双标的合成池里 Z-Score 恒有正负,阈值机制总能换仓,无法隔离止损效果,
     单元测试改用单标的池(评分恒 0,基线永不卖出)。
3. **实验**:32 组(单因子/组合/参数细化/邻域/分时段),脚本 `scripts/reduce_drawdown.py`,
   结果 `output/drawdown_experiments*.csv`。
4. **结论(第一轮)**:推荐止损 6% + 阈值 2.0:年化 43.12%(不降反升)、回撤 -25.35%、胜率 62.5%;
   参数邻域为平台期(非过拟合孤岛);三个分时段回撤全部改善;
   -25.4% 的残余回撤来自 2024-10-17(9·24 行情后创业板50 剧烈反转),所有方案均无法避开。

## 7. 回撤 <20% 攻坚(2026-09-28 第二轮)

1. **回撤解剖**:2024-10 的 -25.4% 是"浮盈回吐"——9·24 后创业板50 六天 +60%,策略持盈 +33%,
   随后 10-09 单日 -15.5%;固定止损锚定成本价(0.769)而价格始终高于 0.90,永不触发。
   → 新增**移动止损 trailing_stop**(锚定持仓期间最高收盘价)。
2. **约束迁移**:移动止损解决 2024-10 后,瓶颈变为 2026-06~09 震荡期(-21.8%)。
   → 新增**入场确认 confirm_days**(空仓时须连续 N 天评分第一),-20.1% 触顶。
3. **结构性突破**:把引擎重构为组合记账(持仓字典 + 槽位等权),支持 `n_hold=2` 双标的分散,
   `select_targets` 推广阈值机制(空槽直接补位,替换在持者需过阈值);
   metrics 配对改为按标的 FIFO。n_hold=1 行为经测试逐点不变。
4. **最终前沿**(6 轮 60+ 组实验):
   - 单持仓极限:34.8% 年化 / -20.1% 回撤(收益优先)
   - **双持仓推荐:22.8% 年化 / -13.3% 回撤**(n_hold=2 + trail8 + min_mom,仅 3 个开关)
   - 分时段回撤 -12.7% / -13.3% / -10.4%,全部 <20%
5. **认知记录**:池子大小必须 > n_hold,否则满仓持有全部标的、阈值机制没有挑战者可换(测试踩坑)。

## 8. 固定止盈实验(2026-09-28 第三轮)

用户问"有止损没有止盈吗"→ 实现 `take_profit`(对成本价浮盈超阈值离场,进同一禁买期)。

- **理论预判被证伪**:原以为止盈砍掉右尾大盈利单会伤收益,实测相反——
  止盈 +25% 后年化 22.8%→26.6%、卡玛 1.72→2.01、最近一年 +12.1%→+29.2%,回撤不变。
- **机理**:移动止损在 +25% 后震荡中只能保住 +15% 左右(回落 8% 才触发);
  止盈在高点直接收割,禁买期躲过回调,资金轮动到池内其他强势标的再赚一轮——
  多段中等盈利 > 一笔大起大落。形成"亏 ≤8% / 盈收 25%"的不对称赔率。
- **稳健性**:邻域 20~40% 平台(取中央 25%);三个分时段全部优于无止盈版;53 测试通过。
- **V3 定稿**:`n_hold=2 + trailing_stop=0.08 + min_momentum=0 + take_profit=0.25`。

## 11. 第五轮:溢价语义修正与"全灭死扛"漏洞修复(2026-09-29)

用户澄清设计意图:**溢价门槛是开仓前的安全检查,不限制已持有的持仓**。逐函数复查
发现两种历史接线都在强制卖出溢价爆表的持仓(F5-2),且第四轮的筛选顺序修复引入了

变成"继续持有死扛"(v3.1 实测 60 天触发),与"全池无趋势时空仓观望"的文档语义相悖。
完整记录见 `docs/audit-report.md` §十,动作摘要:

1. 风控过滤拆两类:**regime 过滤**(min_momentum/ma_filter,离场语义,全灭→空仓)
   与**入场门槛**(premium_max/drop_filter,只拦新开仓,名额递补,不踢持仓);
2. 入场门槛必须先验票再选股——先换血后验票会出现"A 进不来、C 也回不来"的空槽位
   (开发中被测试捕获);
3. 新增 3 个回归测试(92 → 95),变异检验:对第四轮引擎精确杀死两个语义测试;

   2.43→**2.28**;original 与双持仓极简逐位不变(无风控,两种语义等价);
5. 诚实记录:单持仓配置受 F5-1 影响大(`trail8+stop6+thr2+min_mom+confirm3` 年化

## 13. 虚盘自动化:cli status + plan 幂等守卫 + cron 日任务(2026-10-07)

   非交易日自动跳过(execute 检测今日无 bar;plan 靠守卫)。macOS 注意:cron 需完全磁盘
   访问权限(项目在 ~/Desktop 下),并防止到时休眠。
